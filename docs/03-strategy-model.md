# 03 策略模型

## 設計原則

1. **策略就是人類讀得懂的程式。** 每個決策是一個函式，內容是依人類思考順序寫下的 if／else：
   「有人立直、我還差兩步以上 → 棄和，打最安全的牌；否則照牌效……」。不再用一堆數字權重去拼湊判斷。
2. **不分層。** 人類思考時，牌效、打點、讀牌、局勢、詐騙並不是單向的流程，而是彼此交錯影響：
   讀牌結果會改變牌效計算，局勢會改變要不要讀牌，詐騙又取決於對手怎麼讀我。
   所以策略不再拆成固定的六層，而是依「要決定什麼」組織：何切、鳴牌、立直、和牌、開槓、九種九牌。
3. **計算與判斷分開。** 純計算（向聽、進張、點數、現物與筋……）放在 `mj-tools`，只算、不做決定；
   判斷寫在策略目錄中。工具清單見 [`crates/mj-strategy/TOOLS.md`](../crates/mj-strategy/TOOLS.md)。
4. **理由寫在程式裡。** 決策函式用 `ctx.note("…")` 寫下判斷理由，復盤時直接顯示——
   「為什麼這樣打」就是程式走過的那條路。
5. **兩種判斷、兩種評分。**
   - **預測**（某家聽牌了嗎、這張會不會放銃）：全知視角下立刻知道對錯 → 用準確度評分。
   - **決策**（何切、鳴牌、立直、押引）：沒有立即的對錯 → 用反事實模擬評分：改選其他選項重打，比較期望點數。
   兩者都不只看整場輸贏。

## 目錄結構

```
crates/mj-strategy/
  TOOLS.md                       工具手冊（策略編輯者必讀）
  build.rs                       自動掃描 strategy-list，產生模組宣告與策略清單
  src/
    strategy-list/               ← 策略編輯者從這裡開始
      tenhou-normal-4p-hanchan/  一個策略，以規則命名（天鳳一般規則・四人半莊）
        main.rs                  登記：什麼情況呼叫哪一個決策
        memory.rs                對局記憶（整場共用）＋ observe
        decision/                每個檔案匯出一個 decide 函式
          kyuushu.rs win.rs kan.rs discard.rs riichi.rs call.rs
        utils/                   決策共用的輔助判斷
          efficiency.rs defense.rs
          predict/               預測函式（會被全知視角評分）
            tenpai.rs waits.rs
    framework/                   框架：如何呼叫策略（編輯者通常不需要改）
    prelude.rs                   策略檔案開頭 use crate::prelude::*;
crates/mj-tools/                 純計算工具箱
```

目錄與檔名可以用 `-`（建置時自動轉成 `_`）；新增檔案不必寫 `mod` 宣告。

## 決策流程

引擎每次只問「要做哪個動作」。框架把它拆成依人類思考順序的決策：

```
自己的回合：九種九牌? → 和牌? → 開槓? → 何切 → 立直?
他家打牌時：和牌?     → 鳴牌?
```

- 每個決策的結果都是有限的：只能從框架列出的選項中挑一個（例如何切只能從手上的牌中選一張）。
- 能和牌時，「要不要和」與「何切」是分開的兩個決策，依序執行。
- 立直是在何切之後：先決定打哪張，再決定這張要不要立直。

決策函式的簽名：`fn decide(ctx: &Ctx, mem: &mut Memory) -> 結果`。
`ctx` 提供看得到的全部資訊、這次的選項、常用查詢與工具；`mem` 是整場對局共用的記憶。

## 對局記憶

每個策略在 `memory.rs` 定義自己的 `Memory` 結構（編譯器會檢查欄位名稱與型別），
並用 `observe` 從每個事件更新記憶。例如第一個策略記錄：

- 各家立直了幾次；
- 各家用筋牌騙和過幾次 → 讀牌時，這個人的筋牌安全度打折。

## 兩種評分

### 預測：準確度

預測函式放在 `utils/predict/`，計算出機率後以 `ctx.claim(來源, Claim)` 記錄。
`mj predict-eval` 讓策略自我對戰，用完整牌譜重建當時所有人的手牌，判定每個預測的真相，
並依被預測者的情境（巡目、副露組數、是否立直）分組，輸出：

| 指標 | 意義 |
|---|---|
| Brier 分數 | (預測機率 − 真相)² 的平均，越小越好 |
| 技巧分數 | 1 − Brier ÷ 基準 Brier（基準 = 永遠猜平均發生率）；> 0 代表比瞎猜好 |
| 對數損失 | 對「很有把握卻錯了」懲罰較重 |
| 校準表 | 預測 10% 的事，實際上是不是約 10% 發生 |

預測種類（`Claim`）必須能由全知視角判定真相；目前有「是否聽牌」「這張會不會被某家榮和」「本局是否由我和牌」。

### 決策：反事實模擬

`mj evaluate` 正常打完一場，抽樣決策點，對每個決策點：

1. **局面快照**：重播這場對局，在決策點保存完整局面（引擎的 `capture_snapshot`）。
2. **重抽看不到的牌**：產生 R 個「可能的世界」。可分配的牌 = 全部牌 − 決策者看得到的牌（只從決策者視角計算，不會洩漏隱藏資訊），
   隨機分給對手的門前手牌與未摸的牌山；已立直的對手必須拿到聽牌、且沒有振聽的手牌（建構式抽樣）。
3. **每個選項在每個世界中重打**（從快照繼續，強制選這個選項），比較平均結果：
   - `--metric placement`（預設）：打到整場結束，以名次點衡量（(點數 − 30000) ÷ 1000 ＋ 順位馬 ＋ 第一名返點 20）；
   - `--metric points`：只打完這一局，以這一局的點數得失衡量（雜訊小很多，適合快速檢查）。
4. **自動增加世界數**：最佳選項不是實際選擇、但差距還不顯著時，每次再加 `--rollouts` 個世界，直到顯著或達到 `--max-rollouts`。

| 輸出 | 意義 |
|---|---|
| 選到最佳 | 實際選擇就是期望值最高選項的比例（受雜訊影響，僅供參考） |
| 平均損失 ± 標準誤 | 最佳選項的期望值 − 實際選擇的期望值，在所有決策上的平均 |
| 顯著損失比例 | 損失大於 2 倍標準誤的比例——最值得看的指標 |
| 依情境分組 | 何切、鳴牌各依「有無立直者、向聽、巡目、名次」分組 |
| 損失最大的顯著決策 | 附上當時的理由與預測，以及各選項的期望值 |

其他選項：`--kinds discard,call` 只評估某些決策、`--json 檔案` 輸出完整結果、`--omniscient` 改用真實的對手手牌（用來比較）。

各選項使用同一組世界（共同隨機數），差距的雜訊比各自獨立抽樣小得多。
限制：決策者之前已經回應過同一張牌的其他人（例如上家已選擇不鳴）維持原本的選擇；搶槓的詢問點不支援（略過）。

**為什麼要重抽（去除全知）**：同樣 4 場、每場 12 個決策點，以這一局點數衡量時——

| 對手手牌 | 何切平均損失 | 何切顯著損失比例 |
|---|---|---|
| 真實手牌（全知） | 2343 點 | 43.2% |
| 依公開資訊重抽 | 535 點 | 13.5% |

全知版本是用「事後才知道的資訊」評判決策（例如「應該避開實際放銃的那張」），會大幅高估錯誤；重抽版本只用當時能知道的資訊。

**評估的穩定性**：兩組不同的 seed（各 8 場、120 個決策點），何切平均損失 703 ± 80 與 657 ± 80 點、鳴牌 190 ± 99 與 144 ± 88 點，彼此落在誤差範圍內。

### 策略之間的比較：duplicate 對戰

`mj simulate A B --blocks N`：每組用同一個 seed（同樣的牌山），座位依 [A, A, B, B] 輪換打 4 場，
以每組的成對差距計算平均順位差與名次點差的 95% 信賴區間。比較兩個策略或同一策略的兩個版本時，比 `selfplay` 需要的場數少得多。

例：`tenhou-normal-4p-hanchan` 對貪婪機器人，1000 組：平均順位差 −0.854 ± 0.037、名次點差 +30.53 ± 1.23。

A/A 測試：決定性的策略和自己比時，4 種座位輪換只是同樣的對局換了名字，差距必然恰好是 0（代表輪換沒有偏差）；
統計方法本身以帶隨機性的機器人驗證（`mj-sim` 的 `aa_test_has_no_bias`：差距落在信賴區間內）。

### 怎麼用評估結果改進策略

1. 看 `mj predict-eval`：哪個預測校準不好（例如預測 12% 實際只有 9%）→ 修改預測函式的判斷。
2. 看 `mj evaluate`：哪種決策損失最大 → 讀損失最大的例子與當時的理由，找出思路的漏洞 → 修改決策函式。
3. 用 `mj selfplay` 確認整體成績沒有退步。

之後（M8）會加入「可調參數」：在程式中宣告具名的門檻值，讓工具自動搜尋——
預測的參數以預測準確度（對數損失）擬合，決策的參數以反事實模擬的期望值調整，兩者分開進行。

## 第一個策略：tenhou-normal-4p-hanchan

| 決策 | 判斷 |
|---|---|
| 九種九牌 | 繼續打的向聽數 ≥ 4 就流局（國士無雙路線已近時繼續） |
| 和牌 | 一律和牌 |
| 開槓 | 不會讓向聽變差就槓；有人立直時不加槓 |
| 何切 | 有人立直且自己 2 向聽以上 → 棄和，打放銃機率最低的牌；否則牌效：向聽最低 → 進張最多 → 保留寶牌 → 先打幺九牌 |
| 立直 | 聽牌張剩 2 張以上就立直，否則默聽 |
| 鳴牌 | 有人立直且自己 2 向聽以上 → 不鳴；鳴了沒有役 → 不鳴；向聽數沒前進 → 不鳴；其餘選最好的鳴法 |

預測：
- `predict::tenpai`（常駐預測，每回合對三家執行）：立直 → 必聽；否則依巡目與副露數；
  中巡（第 6 巡）起連續摸切 2 次以上時提高機率——副露者每次 +5%、門前不立直者每次 +1%。
  摸切次數記在對局記憶 `tsumogiri_streak`（手切或鳴牌歸 0），模擬人類從中巡才開始留意摸切。
- `predict::waits`：現物 → 字牌 → 筋 → No Chance → 一般危險牌；用過筋牌騙的人筋牌打折。

驗證結果（重構後）：

| 項目 | 結果 |
|---|---|
| 對 3 個隨機機器人（2000 場，輪換座位） | 平均順位 1.000（全部第一名） |
| ×2 對貪婪機器人 ×2（8000 場） | **2.095 ± 0.016**（重構前權重版 2.150）；放銃率 12.8%（重構前 14.9%） |
| 何切一致性（800 手隨機牌、無寶牌、無人立直） | 100% 符合牌理定義 |
| 預測 `predict::waits`（300 場、14 萬筆） | 技巧分數 +0.016：只比基準好一點，0.1–0.2 區間高估（預測 12%、實際 9.3%）→ M6（讀牌）的改進目標 |
| 預測 `predict::tenpai` 依情境（300 場） | 未立直者技巧分數只有 +0.124；副露 3 組時預測 71%、實際 95%（技巧分數 −1.553）→ M6 |
| 預測 `predict::tenpai`（300 場 × 3 組 seed，各約 43 萬筆） | 加入連續摸切判斷後 Brier 0.0545 → 0.0536、0.0553 → 0.0542、0.0542 → 0.0534，技巧分數 +0.586 → +0.593～+0.596（三組 seed 都改善）。基準公式本身的校準仍差（預測 15% 的區間實際不到 1%）→ M6 |

摸切判斷的調整過程（評估工具的典型用法）：最初「每次連續摸切 +8%」反而讓 Brier 變差（0.0545 → 0.0642）。
用預測評估按「副露數 × 巡目 × 連續摸切次數」分組後發現：副露者的連續摸切確實代表聽牌機率上升
（副露 1 組、第 10–13 巡：0 次 55% → 4 次以上 73%），但門前不立直者不論摸切幾次實際聽牌都在 2% 以下
（本評估中的對手一聽牌就立直）。因此改成依副露與否區分。
注意：這個結論取決於對手的打法；人類對手常會默聽，M4 匯入天鳳牌譜後需要重新校準。
