# 04 里程碑

每個里程碑都要能獨立驗收。M0–M10 的完成內容、驗收數據與當時的決策已移到
[`.claude/skills/project-history/`](../.claude/skills/project-history/SKILL.md)（`milestones.md` 原文、`decisions.md` 決策整理）。

## 規劃原則（2026-10-13 重新規劃）

M0–M10 完成了「寫判斷 → 評估 → 讀損失最大的例子 → 修改」這個循環所需的引擎、策略、評估、復盤與練習 App。
現在的瓶頸是**使用者自己改策略、驗證、使用的流程太長**：要在終端機下指令，改完要重新編譯；對局介面也還不夠好用。因此：

1. **策略編輯的便利性與 UI／UX 優先，其他麻將規則延後。**
2. **依難度由低到高排序，前一項是後一項的基礎：**
   - M12 的牌譜檢視器（從牌譜產生幀）會被 M14 的復盤實驗、M15 的「點開任一場」重複使用；
   - M14 的實驗 API 也會被 M15 使用。
3. **為 M16 預留接口。** M15 的所有入口一律透過同一個「參賽者登錄」查策略（`find_strategy_spec`／`mj-app` 的 `entrants()`），
   讓 M16 的參數編輯與重建能直接接上，不必回頭改 M15。
4. **CLI 與 GUI 共用計算。** CLI 指令的核心抽成函式（`mj-sim`、`mj-review`），GUI 透過 `mj-app` 呼叫同一套。
5. **策略本身的改進（Mortal 比較發現的弱點）延到 M15、M16 之後**，讓使用者能用 GUI 自己改、自己驗證。

## 細項

### M11 牌桌介面改善（`app/src/Board.tsx`、`Game.tsx`、`styles.css`；`mj-app` 一處）

1. **文字正置**：旋轉的圖層只放牌河與手牌；名稱、點數、風位等文字放在不旋轉的圖層，各自定位到該家的邊。
2. **四家點數**：`TableView.scores` 已經有，只是沒畫出來。在中央框四邊各顯示一家的風位與點數（像一般麻將遊戲），輪到的那家醒目標示。
3. **版面**：
   - 牌桌大小改依可用寬高計算（取代目前的 `--B = min(640px, 100vh − 150px, 100vw − 400px)`）；
   - 右側欄移到下方，做成可折疊的面板，分頁：提示、紀錄、牌效、對局資訊（seed 等）；
   - 折疊狀態與分頁存在 localStorage。
4. **立直後自動摸切**：合法動作只有摸切時自動送出，由 `mj-app` 的 `HumanSeat` 處理（不必等前端）。
   能自摸或暗槓時仍然詢問；幀中標記「自動」，紀錄顯示「自動摸切」。
5. **音效**：用 Web Audio 合成短音效（不需要音效檔，沒有授權問題）。
   - 觸發：播放到立直宣言、`riichi_accepted`、`call`、`win` 的幀；
   - 設定列加音量開關。
6. **同種牌標示**：React context 記住「目前指向的牌」，`Tile` 滑鼠移入時設定。
   - 同種的牌（赤五視為 5）加上 `mark-same` 樣式；
   - 範圍：牌河、副露、寶牌指示牌、自己的手牌、提示與紀錄中的牌圖。

### M12 牌譜存取與檢視器

1. **匯出**：沿用現有的 mjai 牌譜下載。
   - 桌面版改用 Tauri 的 dialog／fs 外掛另存新檔，網頁版維持下載；
   - 參賽者、seed、提示策略寫進 mjai `start_game` 的擴充欄位。
2. **讀入**：
   - API `load_log`（檔案內容）→ `mj_paifu::load`（天鳳 XML／JSON、mjai）→ 保存在 `App`；
   - 前端：開啟檔案 → 選玩家 → 既有的復盤流程（`review_game`）。
3. **檢視器**：API `log_frames(座位 | 全知)` 用 `table::TableBuilder` 把牌譜事件轉成幀。
   - 前端 `Viewer.tsx`：上一打／下一打、跳到某局、切換視角；
   - 復盤畫面改用它（目前復盤依賴 session 的幀，讀入的牌譜沒有 session）。
4. **測試**：匯出 → 讀入 → 重播點數一致；檢視器的幀與引擎視角一致（沿用 `check_table`）。

### M13 和牌路線提示

1. `mj-tools` 新增 `hand::win_routes(view, hand, limit)`（純計算，策略也能用）：
   - 向聽數 ≤ 2 時，搜尋「每步都讓向聽數下降」的摸牌組合；
   - 把終點的和牌形依需要的牌分組；
   - 用 `tools::value::win_value` 估算點數（門前時列出立直與默聽），依點數與容易程度排序，回傳前幾名。
     例如「還要 3s、6p → 斷么九・平和・寶牌 1，約 3900」；
   - 容易程度以需要的牌的剩餘張數粗估。
2. 提示面板新增「和牌路線」分頁；`TOOLS.md` 同步。
3. 效能：在計算提示時執行，向聽數 > 2 時不算，並設搜尋上限。

### M14 反事實實驗

1. `mj-app` 新增背景工作 `experiment`（可查進度、可取消）：
   - 對局中：用目前為止的紀錄產生牌譜，`mj_paifu::replay::capture` 在這次詢問保存快照；
   - 復盤時：對讀入或剛打完的牌譜做同樣的事；
   - 用 `mj_sim::counterfactual::evaluate_snapshot` 重抽世界，每個選項以 `Force` 強制後，四家依策略打完；
   - 結果擴充：除了名次點、本局點數，另外統計本局和了率、放銃率、平均順位。
2. 前端：在選擇點按「實驗」→ 勾選要比較的選項、重打次數、名次點或本局點數 → 表格與誤差，並標出策略的選擇。
3. 限制：對手是 Mortal 時，重打改用策略代替（Mortal 的狀態不能在快照點複製），畫面上要註明。

### M15 GUI 對戰測試平台

1. `mj-app` 的「工作」系統：`selfplay`、`simulate`（含場地對戰）、`predict-eval --seats`、`evaluate`。
   - 背景執行，可查進度、可取消；
   - 結果存成 JSON 檔（資料目錄），重開 App 後還能查看；
   - CLI 與 GUI 共用同一套計算函式。
2. 對局的重現：每場記錄 seed、座位配置、參賽者規格。
   - 決定性的參賽者可以從這些資料重新產生牌譜，不必保存全部紀錄；
   - 含 Mortal 或亂數機器人的對局另外保存牌譜檔。
3. 前端「測試」頁：
   - 參賽者選擇器（策略、`@參數` 覆寫、機器人、mjai）與對戰設定；
   - 結果：彙總表、信賴區間、每局統計；
   - 對局清單（可依名次、點差排序）→ M12 的檢視器 → 每個決策顯示策略的理由，可進行 M14 的實驗。

### M16 策略編輯流程（A＋B）

方案比較與否決的做法見 project-history 的 `decisions.md`「規劃」一節。

1. **A. 參數即時編輯**：GUI 列出策略的 `Param`（名稱、說明、預設、範圍、目前值），修改後立即用於對局與測試
   （透過現有的 `策略@覆寫`），可另存成參數檔（`mj params` 的格式），也能套用 `mj tune` 的結果。
   - 桌面安裝版也能使用（不需要工具鏈）。
2. **B. 監看與自動重建**：新增 `mj dev`（或 `mj serve --dev`）。
   - 監看 `crates/mj-strategy/src/strategy-list` → 自動 `cargo build` → 重啟服務；
   - 前端偵測到重啟後自動重連，回到原本的畫面：設定與測試頁照舊，進行中的對局以 seed＋動作序列重建；
   - 編譯錯誤與警告顯示在 GUI；
   - 第一步實測增量編譯時間；太長時，另設編譯較快的 profile，或把策略拆成獨立 crate 縮小重建範圍。
   - 需要 Rust 工具鏈，只用於開發環境（容器內的網頁版，或 Mac 上 `npm run tauri dev`）；桌面安裝版不能改策略程式。
3. 驗收時記錄：改參數到生效、改程式到可用的等待時間。
