## 規劃原則（2026-10-13 重新規劃）

M0–M10 完成了「寫判斷 → 評估 → 讀損失最大的例子 → 修改」這個循環所需的引擎、策略、評估、復盤與練習 App。
現在的瓶頸是**使用者自己改策略、驗證、使用的流程太長**：要在終端機下指令，改完要重新編譯；對局介面也還不夠好用。因此：

1. **策略編輯的便利性與 UI／UX 優先，其他麻將規則延後。**
2. **依難度由低到高排序，前一項是後一項的基礎：**
   - M12 的牌譜檢視器（從牌譜產生幀）會被 M14 的復盤實驗、M15 的「點開任一場」重複使用；
   - M14 的實驗 API 也會被 M15 使用。
3. **為 M16 預留接口。** M15 的所有入口一律透過同一個「參賽者登錄」查策略（`find_strategy_spec`／`mj-app` 的 `entrants()`），
   讓 M16 的參數編輯與重建能直接接上，不必回頭改 M15。
4. **CLI 與 GUI 共用計算。** CLI 指令的核心抽成函式（`mj-sim`、`mj-review`），GUI 透過 `mj-app` 呼叫同一套。
5. **策略本身的改進（Mortal 比較發現的弱點）延到 M15、M16 之後**，讓使用者能用 GUI 自己改、自己驗證。

**完成內容**（2026-10-13）

- `mj-tools` 的 `routes::win_routes`（純計算，策略也能用；`TOOLS.md` 已補）：
  - 從目前的手牌出發，每一步摸一張讓向聽數前進的牌、打一張維持前進後向聽數的牌，直到和牌（最短路線：摸牌數 = 向聽數 + 1）；
  - 摸牌後（3k+2 張）先打一張，只考慮打完向聽數最低的打法；
  - 同樣的局面（手牌＋已摸的牌）只展開一次，節點上限 6 萬；向聽數 > 2 不算；
  - 完成形以每張要摸的牌當和牌張各算一次榮和（門前時假設立直），取最高者；
  - 機會 = 要摸的牌的剩餘張數組合數相乘；同樣要摸的牌、同樣點數與役的路線只留一條；依機會排序，點數最高的路線不在前幾名時另外附上。
  - 近似：赤寶牌依目前持有的計算；裏寶牌不計。
- 提示（`mj-app` 的 `Hint.routes`）：打牌時附上前 6 條，第一張要打的牌必須是合法的打法（食替禁止的牌不列）；役之後列寶牌、赤寶牌。
- 前端：下方面板新增「和牌路線」分頁：要打、要摸、完成形（標出和牌張）、役、榮和點數（符番或滿貫等級、是否假設立直）、機會（列出的路線之間的比例）。

驗證：
- `mj-tools` 測試：
  - 兩面聽牌的兩條路線（立直・斷么九・平和 3900，依剩餘張數排序）；
  - 一向聽的每條路線完成形都是和牌形，而且等於「原手牌 − 打掉 + 摸到」；
  - 摸牌後第一張要打的牌正確；
  - 副露無役時點數為 0；
  - 兩向聽算得出來、三向聽以上不算。
- 速度：隨機 300 手兩向聽的 14 張手牌，平均 2.2 ms、最慢 14 ms（release）。
- `mj-app` 測試：照提示打完整場時常有路線，每條路線要打的第一張都是合法動作、和牌張是要摸的牌之一。
- Playwright：對局中兩向聽與聽牌時的分頁截圖。

### M14 反事實實驗

1. `mj-app` 新增背景工作 `experiment`（可查進度、可取消）：
   - 對局中：用目前為止的紀錄產生牌譜，`mj_paifu::replay::capture` 在這次詢問保存快照；
   - 復盤時：對讀入或剛打完的牌譜做同樣的事；
   - 用 `mj_sim::counterfactual::evaluate_snapshot` 重抽世界，每個選項以 `Force` 強制後，四家依策略打完；
   - 結果擴充：除了名次點、本局點數，另外統計本局和了率、放銃率、平均順位。
2. 前端：在選擇點按「實驗」→ 勾選要比較的選項、重打次數、名次點或本局點數 → 表格與誤差，並標出策略的選擇。
3. 限制：對手是 Mortal 時，重打改用策略代替（Mortal 的狀態不能在快照點複製），畫面上要註明。

**完成內容**（2026-10-13）

- `mj-sim` 的 `counterfactual::run_experiment`：在快照點比較指定的幾個選項。
  - 每個世界依決策者看得到的資訊重抽，各選項強制選定後四家依策略打完（同一組世界，成對比較）；
  - 各世界平行計算，可查進度、可取消（以已完成的世界計算）；
  - 結果：平均（本局點數或名次點）±標準誤、與基準選項（策略的選擇）的成對差±標準誤、本局和了率、放銃率；名次點時另有平均順位。
- `mj-app` 的 `experiment.rs`：
  - 對局中的快照：session 用 `Recorder` 記下四家的每個動作；實驗時以同一個 seed 照紀錄重播（`Scripted`，策略在旁觀），在這次詢問保存快照。
    不必重新計算 AI，所以對手是 Mortal 也能做（原計畫要求 Mortal 時改用策略，現在只有重打時用策略）；
  - 重播到的局面必須與當時人類看到的視角完全相同（session 保存每次詢問的視角來比對），否則回報錯誤；
  - 讀入的牌譜：`mj_paifu::replay::capture`，策略旁觀；
  - 同時只有一個實驗；開始新的會取消舊的；開新對局、讀入新牌譜時清掉結果。
- API：`start_experiment`、`experiment`、`cancel_experiment`；提示的決策附 `kind_key`（決策種類代號）。
- 前端 `Experiment.tsx`：
  - 對局中：提示裡每個決策的「實驗」按鈕 → 下方面板的「實驗」分頁（面板自動拉高）；
  - 復盤：決策詳情的「實驗：比較這個決策的選項」；
  - 勾選要比較的選項、世界數（32–256）、衡量方式（本局點數／名次點）；
  - 結果依平均排序，標出策略與玩家的選擇，差值超過 2 倍標準誤時著色。

驗證：
- `mj-app` 測試（`tests/experiment.rs`）：
  - 對局中對何切做實驗（重播的局面與當時的視角一致）；
  - 讀入的天鳳牌譜對復盤中的何切做名次點實驗（有平均順位）；
  - 大量世界時取消會很快結束。
- Playwright：對局中與復盤中實際操作。何切 12–14 個選項、32 個世界：本局點數約 1 秒，名次點約 3 秒（10 核）。

### M14.5 多個顧問（2026-10-20 插入）

使用者在 M15 之前加入的需求：

1. 環境允許時（已用 `tools/mortal/setup.sh` 安裝），Mortal 可以選為「提示與復盤的策略」；Mortal 不顯示思考過程，只列出各動作的機率。
2. 「提示與復盤的策略」可以選最多三個策略／AI，對局中同時列出它們的選擇。
3. 開局設定的策略選項標上最後更新時間，由新至舊排序；M16 完成後，參數調整與監看到策略異動時要即時更新。

**完成內容**（2026-10-20）

- 顧問（`mj-review` 的 `advisor` 模組，對局與復盤共用）：
  - `Watcher` 旁觀並記下每次詢問的回答：策略有決策紀錄（理由），mjai AI 有各動作的機率；
  - `pick` 把回答對應到某個決策的選項（同種類、同選項的決策紀錄優先，否則用 `option_of_action`）；
  - Mortal 的機率：`mj-mjai` 的 `mortal::policy` 解讀回應的 `meta.q_values`／`mask_bits`（46 種動作，吃的高中低、槓的 `kan_select`、赤五），
    取 Q 值的 softmax（溫度 1）。只是把 Q 值的相對好壞換成比例，Mortal 實際上一律選 Q 值最高的；
  - 立直：Mortal 先決定立直、再決定打哪張；旁觀模式的 `mj_peek` 回應也保存下來，另列「立直後打」的機率；
  - Mortal 當顧問時自動加 `--q-values`（關閉 quick eval，只有一個選擇時也回 Q 值；每次約 17 ms）。
- `mj-app` 的 `advisor.rs`：顧問清單（1–3 個、不重複、內建機器人不可）。
  - 決策結構與重打需要策略：用顧問中的第一個策略（「基礎策略」）；都是 AI 時用預設策略，但不顯示它的理由；
  - 第一個顧問是主要的：提示標示它的動作，復盤以它為比較基準（`Reviewed::strategy`；它走了另一條路的決策算無法比較）。
- 提示（`Hint::advisors`）：每個顧問的動作、決策（附每個顧問在這個決策的選擇 `picks`）、AI 的機率。
  AI 的決策是基礎策略的決策結構、選擇換成 AI 的，所以 AI 的選擇也能做實驗（重打用基礎策略）。
- 復盤：`mj_review::Options::advisors`／`base_advisor`；`Reviewed::picks`、`policies`；`GameReview::advisors`。
  App 的復盤可以重選顧問（預設為牌譜記載的，`mj_meta.advisors`）。
- 實驗：`ExperimentRequest::strategy` 指定用哪個策略顧問重播與重打（預設基礎策略）；結果表標出各顧問的選擇。
- 更新時間：`Strategy::updated()`。
  - `framework/source.rs` 的 `dir_updated`：git 最後提交策略目錄的時間，與未提交的修改檔案的修改時間取較晚者（clone 後檔案時間都一樣，所以不能只看檔案時間）；沒有 git 時用檔案時間；
  - build.rs 算一次嵌入執行檔；執行時原始碼目錄還在就重新計算（改了策略不必重新建置，選單就會更新）；
  - Mortal 用權重檔的時間；內建機器人沒有時間，排在最後；
  - API `strategies`／`entrants` 附 `kind`、`updated`，由新至舊排序。
- 前端：`Advisors.tsx`（顧問選單、時間格式、機率條）；開局設定與復盤設定的三格選單；提示面板各顧問並排（手機寬度時上下排）。

驗證：
- `mj-mjai`：Q 值解讀（編號、赤五、摸切、softmax）；`mj-review`：第一個顧問換成另一個策略時，基準與選擇正確、理由不變；
- `mj-app`（`tests/advisors.rs`）：兩個策略、Mortal＋策略、只有 Mortal 三種組合，對局中每次詢問的提示與對局後的復盤；不合法的顧問清單；
- Playwright：三個顧問（讀牌押引、Mortal s42、押引期望值）的對局提示、對 Mortal 的何切做實驗、以 Mortal 為基準復盤。

### M16 策略編輯流程（A＋B）

方案比較與否決的做法見 project-history 的 `decisions.md`「規劃」一節。

1. **A. 參數即時編輯**：GUI 列出策略的 `Param`（名稱、說明、預設、範圍、目前值），修改後立即用於對局與測試
   （透過現有的 `策略@覆寫`），可另存成參數檔（`mj params` 的格式），也能套用 `mj tune` 的結果。
   - 桌面安裝版也能使用（不需要工具鏈）。
   - 參數覆寫後的策略也要有更新時間（例如參數檔的時間），讓 M14.5 的選單即時反映。
2. **B. 監看與自動重建**：新增 `mj dev`（或 `mj serve --dev`）。
   - 監看 `crates/mj-strategy/src/strategy-list` → 自動 `cargo build` → 重啟服務；
   - 前端偵測到重啟後自動重連，回到原本的畫面：設定與測試頁照舊，進行中的對局以 seed＋動作序列重建；
   - 編譯錯誤與警告顯示在 GUI；
   - 第一步實測增量編譯時間；太長時，另設編譯較快的 profile，或把策略拆成獨立 crate 縮小重建範圍。
   - 需要 Rust 工具鏈，只用於開發環境（容器內的網頁版，或 Mac 上 `npm run tauri dev`）；桌面安裝版不能改策略程式。
3. 驗收時記錄：改參數到生效、改程式到可用的等待時間。
