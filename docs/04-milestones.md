# 04 里程碑

每個里程碑都要能獨立驗收。順序的原則是：先讓「能打完一局」與「能比較強弱」成立，再逐層加入策略。

| # | 內容 | 驗收條件 | 狀態 |
|---|---|---|---|
| **M0** | 專案骨架：workspace、crates、`mj-core` 牌型別、`mj-strategy` 框架（Consideration / Modifier / Profile / Decider / Trace）、CLI、文件 | `cargo test --workspace` 通過；`mj check profiles/example.toml` 成功 | ✅ |
| **M1** | 規則引擎：日麻完整流程（吃碰槓、立直、和牌、流局、連莊）、役與符的點數計算、seed 牌山；向聽與進張計算 | 點數計算通過大量已知案例；隨機 AI 跑 10 萬局不 panic；向聽結果和現有工具一致 | |
| **M2** | 牌效層 L2：`efficiency.*` 考量、基本立直與鳴牌判斷；第一個可用的 profile | 牌效 AI 對隨機 AI 平均順位 < 1.5；何切題和現有牌理工具的一致率高 | |
| **M3** | 模擬器：duplicate、平行化、統計報告（平均順位、和了率、放銃率、信賴區間）、`mj simulate` | 單機每分鐘 ≥ 數千場半莊；A/A 測試的差距落在誤差內 | |
| **M4** | L3 打點、L4 防守（現物、筋、壁、押引）、L5 局勢修正器 | 每個模組的消融實驗都顯示有正貢獻 | |
| **M5** | L1 讀牌：機率化剩餘牌、聽牌率和危險度模型（用天鳳公開牌譜統計校準） | 危險度預測的校準曲線；接入 L2 後勝率提升 | |
| **M6** | 自動調參 `mj tune`、mjai bridge（和外部 AI 對戰或拿來比較） | 調參後的 profile 顯著優於手調版本；能和外部 AI 完成對戰 | |
| **M7** | Tauri 桌面練習 App：牌桌、人機對戰、即時提示開關；`mj serve` 開發模式 | 三平台都能安裝並完成一場半莊 | |
| **M8** | 復盤：牌譜匯入、Trace diff 解說、多 profile 對照 | 匯入使用者的實戰牌譜，產生可讀的逐手報告 | |
| **M9** | L6 印象操作：二階信念、迷彩和威嚇考量 | 對使用讀牌的 AI 能測出效果，或結論為無效並記錄原因 | |
| 之後 | 其他規則（台灣 16 張等）、網頁版（WASM）、LLM 潤飾解說 | 新規則不需要修改 strategy、sim、review | |

## 建議的下一步（M1）

1. `mj-core`：紅寶牌表示、副露（meld）型別。
2. `mj-calc`：查表式向聽計算，加上單元測試（對照已知手牌）。
3. `mj-rules::riichi`：和牌判定、役、符、點數。這是最容易出錯的部分，要建立大量測試案例。
4. `mj-engine`：以 `PlayerView` 為邊界的狀態機，以及 `Player` trait（`fn act(&mut self, view, legal) -> Action`）。
