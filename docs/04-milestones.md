# 04 里程碑

每個里程碑都要能獨立驗收。

## 規劃原則（M2.5 重構後）

策略改為人類編寫的 if／else 決策程式後，開發方式變成一個循環：

```
寫判斷 → 評估（預測：準確度；決策：反事實期望值）→ 讀損失最大的例子與當時的理由 → 修改判斷
```

因此里程碑依下列原則排序：

1. **評估工具先行。** 評估的可信度決定了之後所有策略修改的方向，所以先把反事實模擬去除全知、改用名次期望值，並能比較兩個策略版本。
2. **基礎設施與策略內容分開。** 標「策略」的里程碑主要是在 `strategy-list` 中寫判斷（使用者可親自編寫），基礎設施里程碑則提供需要的工具、預測種類與評估方式。
3. **共用的東西提早做。** 牌譜匯入同時供讀牌校準（人類資料）與復盤使用，所以放在策略內容之前。
4. **復盤先於 App。** 復盤由既有的決策紀錄（理由）與反事實期望值組成，先以 CLI／JSON 完成；桌面 App 只是把它和牌桌畫出來。

### M3 細項

1. **反事實評估 v2**
   - 對手手牌與未見牌依公開資訊重新抽樣（去除全知）；
   - 結果改用名次期望值（含順位馬與返點），也保留點數得失；
   - 自動增加重打次數，直到最佳選項與實際選擇的差距顯著或達到上限；
   - 優先抽樣「選項之間差異大」的決策點，減少浪費在顯而易見決策上的計算。
2. **報告**：依決策種類 × 情境（有無立直者、向聽數、巡目、名次）分組統計損失；評估結果輸出 JSON（之後的復盤與 App 直接讀取）。
3. **策略比較**：`mj simulate` 以 duplicate（同牌山輪換座位）比較兩個策略或同一策略的兩個版本；A/A 測試驗證沒有偏差。
4. **常駐預測** ✅（提前完成）：`book.predict_each_turn` 登記「每回合都執行」的預測函式，即使決策沒用到也能被評估（`predict::tenpai` 已使用）。
5. **預測報告**：依情境（巡目、副露數、是否立直）分組的準確度。

## M1 完成內容

- `mj-core`：`Pai`（赤寶牌）、`Meld`（吃、碰、明槓、暗槓、加槓）。
- `mj-calc`：精確向聽（每種花色用 DP 計算「最少還需要幾張牌」再合併，結果經過定義性質測試驗證）、進張、聽牌、和牌拆解。
- `mj-rules::riichi`：全部役種與役滿（含複合役滿、累計役滿）、符、點數；20 萬手隨機和牌與 Python `mahjong` 函式庫**零差異**。
- `mj-engine`：完整對局流程。包含吃碰槓與食替、立直與雙立直、一發、各種振聽（捨牌、同巡、立直）、搶槓（國士可以搶暗槓）、海底與河底、嶺上、天和與地和、雙響（三家和了算流局）、包牌、流局聽牌料、流局滿貫、九種九牌、四風連打、四家立直、四槓散了、連莊與本場、西入、擊飛、和了止め。另外支援指定牌山（測試與牌譜重播）。
- `mj-sim::bots`：`RandomBot`、`GreedyBot`（向聽和進張最佳化，供模糊測試和當作基準）。
- `mj selfplay`：平行自我對戰並統計結果；`fuzz` profile 會在每回合檢查牌數與點數守恆。
- 驗證方式詳見 [02-architecture.md 的測試策略](02-architecture.md#測試策略)。

## M3 完成內容

- 引擎：局面快照（`capture_snapshot`：在「即將第 n 次詢問某座位」時保存局面）、從快照繼續（`resume_game`，打到本局或整場結束）、
  依決策者視角重抽看不到的牌（`Snapshot::determinize`；立直者以建構式抽樣得到聽牌且未振聽的手牌）。

- 反事實評估 v2：從快照在 R 個重抽世界中重打；名次點或本局點數；差距不顯著時自動增加世界數；

- `mj simulate`：duplicate 對戰（同牌山、[A, A, B, B] 座位輪換），成對差距與 95% 信賴區間。
- 常駐預測（`book.predict_each_turn`）；預測報告依被預測者的巡目、副露、立直分組。
- 框架：決策紀錄附情境（`Situation`）、預測紀錄附被預測者情境（`TargetSituation`）；策略玩家可以複製（`Memory` 需要 `Clone`）。

## M4 完成內容

- 新 crate `mj-paifu`：
  - `tenhou_xml`（天鳳原始 mjlog，可大量下載）與 `tenhou_json`（tenhou.net/6 格式）解析成共通的 `GameRecord`。
    JSON 把每家的摸牌與打牌分開記錄，解析時模擬輪轉排出時間順序。
  - `replay`：由配牌與摸牌順序還原每局牌山，四家照牌譜出牌讓**引擎重新打一次**，再比對每局開始的局數、本場、供託、點數，
    每局結束與終局點數。得到的是一般的 `GameResult`（完整事件紀錄＋牌山），重播、預測判定、快照都能直接使用。
  - `DecisionPoint`：每次詢問的視角（`PlayerView`）、合法動作與牌譜中的選擇——M7 復盤的輸入。
  - 旁觀（shadow）：策略收到同樣的事件與詢問並做預測，但動作照牌譜。
- `mj import <檔案或目錄>`：批次匯入並驗證，`--dump` 輸出引擎事件紀錄；`mj predict-eval --logs <目錄>`：在真人對局上評估預測。
- `tools/fetch-tenhou.sh`：下載鳳凰卓牌譜（XML＋JSON）到 `data/tenhou/`（不納入版本控制）；
  `crates/mj-paifu/tests/data/` 放 7 場匿名化牌譜（雙響、各種槓、流局滿貫、九種九牌、東風戰、西入）供測試。

### 驗收

| 條件 | 結果 |
|---|---|
| 匯入的點數與原牌譜一致 | 天鳳鳳凰卓 **302 場、3195 局**（和牌 2682、雙響 15、流局 528）全部零差異；XML 與 JSON 各自匯入都一樣，兩種格式解析出的動作完全相同 |
| 在決策點重建 `PlayerView` | 19.6 萬個決策點；測試確認選擇都在合法動作中、手牌張數正確、詢問次數與引擎一致 |
| 對人類牌譜計算預測準確度 | 302 場、59.5 萬筆預測，2.8 秒（見下） |

實戰牌譜同時是引擎的獨立驗證，找出並修正了兩個與天鳳不同的規則：
1. 最終局莊家第一名時發生**途中流局**（九種九牌等），引擎原本以和了止め結束整場；天鳳會繼續（只有莊家和牌或流局聽牌時才結束）。
2. 立直者的聽牌張被別人**暗槓**，引擎原本判為「放過和牌」而立直振聽；暗槓只有國士無雙能搶，其他人本來就不能和，不算放過。

### 對真人對局的預測準確度（與自我對戰比較）

| 項目 | 自我對戰（300 場） | 天鳳鳳凰卓（302 場） |
|---|---|---|
| `predict::tenpai` 整體技巧分數 | +0.593 | +0.425 |
| 未立直者：平均預測／實際聽牌率／技巧分數 | 0.196 ／ 7.3% ／ +0.125 | 0.222 ／ 9.1% ／ +0.063 |
| 副露 1 組：平均預測／實際 | 0.391 ／ 42.6% | 0.388 ／ 25.2% |
| 副露 3 組：平均預測／實際 | 0.706 ／ 94.8% | 0.754 ／ 84.0% |
| `predict::waits` 技巧分數 | +0.016 | +0.027 |

所以讀牌的預測應以天鳳牌譜校準（M6），不能只靠自我對戰。

## M5 完成內容

- 押引：有人立直時每張候選牌算「和牌機率 × 和牌價值 − 放銃機率 × 對手打點」，取最高者，
  同時涵蓋對攻、回し打ち、退一步、棄和（細節與各項估計方式見 03 文件「押引」）。
- 新預測 `predict::win`（`IWinThisHand`，常駐）：一巡一巡往後推的和牌機率；`predict::tenpai`、`predict::waits` 拆出不記錄預測的 `estimate`。
- 立直或默聽：無役立直；默聽滿貫、牌山將盡、最終局第一名時默聽。
- 鳴牌：有人立直時只有鳴了就聽牌才鳴；不做「非役牌、還要 2 向聽以上、寶牌不到 2 張」的鳴牌。
- 牌效：打出寶牌時進張打 85 折（差不多就留寶牌）。
- 工具：`tools::value::tenpai_value`（聽牌手的平均榮和點數）、`points_for_han`。
- 策略目錄改為「規則／策略」兩層：`tenhou-normal-4p-hanchan/push-fold`（M5 的策略）與 `tenhou-normal-4p-hanchan/efficiency-fold`（M4 時凍結，作為比較基準）；
  每個策略必須有 `README.md`（標題、一段摘要、特色），`mj strategies` 與日後 GUI 的策略選單顯示這份說明。
- 引擎修正（反事實評估時發現的崩潰）：在回應階段保存的快照，重抽手牌後，之前已回答的對手要依新手牌重新詢問
  （原本沿用依真實手牌做的吃碰決定，會用到已不在手上的牌，也等於洩漏了他們的決定）。加了回歸測試。

### 驗收

| 條件 | 結果 |
|---|---|
| 對前一版（M4）顯著更好 | duplicate 5000 組：平均順位差 **−0.130 ± 0.018**、名次點 **+3.55 ± 0.59**（seed 400000；另一組 seed −0.136 ± 0.018、+3.95 ± 0.60） |
| 對貪婪機器人顯著更好 | duplicate 2000 組：平均順位差 −0.934 ± 0.025、名次點 +32.60 ± 0.85（M4 版本同條件 −0.837 ± 0.026、+29.92 ± 0.86） |
| 放銃率接近人類中上級 | 四家自我對戰 2000 場：和了率 20.8%、**放銃率 12.5%**、立直率 25.1%（M4 版本 23.4%／15.9%／27.7%；天鳳鳳凰卓 302 場：21.0%／12.2%／17.0%） |
| 反事實評估的平均損失明顯下降 | **只部分達成**：40 場、本局點數衡量，何切 599.5 ± 35.3 → 547.2 ± 32.7、鳴牌 178.4 ± 44.7 → 145.3 ± 39.3、立直 131.7 ± 55.6 → 93.4 ± 54.8 點，都下降但差距在 2 倍標準誤以內 |

反事實評估的下降不明顯，原因：

- 有人立直時的何切，損失 281 → 268 點，本來就不高。押引的效果主要在「哪些局面不放銃」，局部的單手損失看不太出來，
  duplicate 對戰則清楚顯示整體變強。

## M7 完成內容

- `mj-review` crate 與 `mj review <牌譜> [--player 名稱 | --seat N] [--json 檔案]`：
  1. 照牌譜重播，四家掛策略旁觀：策略做同樣的決策（選項、選擇、理由），動作照牌譜；
  2. `framework::option_of_action` 把玩家的實際動作對應到策略的決策選項（選項列法與 `BookPlayer` 共用）；
     玩家走了另一條路（例如策略在想何切，玩家卻自摸了）的決策無法比較，差異會出現在更早的決策上；
  3. 選擇不同的決策：`mj_paifu::replay::capture` 重播到那一刻保存快照（旁觀的策略玩家直接當作之後的玩家），
     依玩家當時看得到的資訊重抽，用 `counterfactual::evaluate_snapshot` 讓各選項各重打 64 次（`--omniscient` 可改用真實手牌）；
  4. 差異分類：何切（向聽倒退、進張較少、牌效相同的打牌順序、牌效相近、打掉寶牌、有人立直時的過度防守／放銃風險）、
     鳴牌（多鳴、漏鳴、鳴法不同）、立直（默聽／立直）、和牌（見逃）、開槓、九種九牌；

     期望值最高的幾個選項、策略的理由；最後依決策種類與差異類型彙整平均差值。JSON 輸出供 M9 的 App 使用。

### 統計方法的修正（開發過程中發現）

第一版拿玩家的選擇和「期望值最高的選項」比，並在差距顯著時提早停止重打。實際跑過鳳凰卓牌譜後發現這會產生大量誤報：
- 最高的選項是從十幾個帶雜訊的估計中挑出來的，本身就偏高（挑選偏差），連早巡打哪張字牌都會被判成「失誤」；
- 一場有幾十個決策要評估，2 倍標準誤的門檻下，即使兩個選項其實一樣好，每個方向也有約 2.3% 會被判成顯著；提早停止會讓這個比例更高。

改成：
- 只比較**玩家與策略**兩個選項（同一組世界的成對差值，沒有挑選偏差），固定 64 個世界；
- 單一決策的「明顯失誤」用 3 倍標準誤（`MISTAKE_Z`）；
- 主要的統計是**同一類決策的平均差值 ± 標準誤**（至少 10 個決策才判斷顯著，`MIN_GROUP`）。

### 驗收：5 場鳳凰卓牌譜、20 位玩家（2026-10-08 00 時）

每位玩家約 130–200 個可比較的決策，與策略選擇相同 45–71%；選擇不同的 1282 個決策全部評估，共 381 秒（約 19 秒／人／場）。

| 類型 | 次數 | 平均差值（策略 − 玩家，點） | 解讀 |
|---|---|---|---|
| 全部 | 1282 | **−65 ± 17** | 選擇不同時，鳳凰卓玩家平均比策略好 |
| 漏鳴（玩家不鳴、策略會鳴） | 44 | **−660 ± 180** | 策略在這些局面鳴太多（改進目標） |
| 牌效相近（打點、形狀） | 176 | **−133 ± 50** | 牌效接近時，玩家看打點與形狀的判斷較好 |
| 牌效相同（打牌順序） | 458 | −31 ± 18 | 幾乎沒差 |
| 進張較少 | 355 | −35 ± 26 | 玩家犧牲進張的選擇並不比較差 |
| 過度防守（玩家打現物、策略對攻） | 20 | +271 ± 160 | 策略的押引可能較好（不顯著） |
| 默聽（策略立直） | 42 | +85 ± 85 | 不顯著 |

單一決策標成「明顯失誤」的有 7 個、「玩家明顯較好」18 個。復盤因此也成為改進策略的工具：
在高手的牌譜上，平均差值顯著為負的類型就是策略的弱點。

限制：
- 重抽對手手牌是均勻隨機的（只限制立直者聽牌），讀牌的線索在重抽後消失（見 M6）；
- 預設以「這一局的點數」衡量（`--metric placement` 可改用名次點，較慢、雜訊較大）；
- 使用者自己的牌譜目前只支援天鳳格式（mjlog XML／JSON）。
