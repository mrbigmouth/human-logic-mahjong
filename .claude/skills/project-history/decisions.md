# 已定案的設計決策（M0–M10）

每條：決策、理由、出處（`milestones.md` 的章節）。會影響現在寫程式的不變條件仍寫在 `CLAUDE.md`；這裡是「為什麼當初這樣決定」。

## 策略架構

- **策略寫成 if／else 決策函式，不用「考量＋權重」**（M2.5）。
  使用者要求策略讀得懂、能逐行改；權重式（六層架構、響應曲線、TOML 側寫）已移除。改寫後強度不變並略有提升（對貪婪機器人平均順位 2.150 → 2.095）。出處：M2、M2.5 完成內容。
- **工具（`mj-tools`）只做純計算，判斷寫在策略裡**（M2.5）。工具可以共用、測試；「該怎麼打」留給策略編輯者。
- **策略必須是決定性的**（M3）。快照與反事實評估靠「同牌山重播會走到同一個詢問點」。
- **規則／策略兩層目錄、每個策略有 README**（M5）。舊版策略凍結為比較基準：`efficiency-fold`（M4）、`push-fold`（M5）。

## 評估方法

- **反事實評估去除全知：依決策者視角重抽看不到的牌**（M3）。全知版本的何切平均損失 2343 點，重抽後 535 點；全知會高估「看得到對手手牌」的選項。出處：M3 驗收。
- **重抽是均勻隨機（只限制立直者聽牌），讀牌線索在重抽後消失**（M3／M6／M7 的已知限制）。因此讀牌對決策的效果，反事實評估量不準，要用對戰（duplicate）或牌譜衡量。
- **策略之間的比較用 duplicate（同牌山輪換座位），不用獨立對局**（M3）。成對比較的雜訊小得多；A/A 測試確認沒有偏差。
- **復盤只比較「玩家 vs 策略」的成對差值，不和「最高期望值」比**（M7）。
  最高者是從十幾個帶雜訊的估計中挑出來的，有挑選偏差；提早停止也會增加誤報。
  單一決策的「明顯失誤」用 3 倍標準誤，主要看同類決策的平均差值。出處：M7「統計方法的修正」。
- **預測與押引使用分開的兩組參數**（M8）。
  以牌譜校準的 `win.*` 直接用在押引反而變弱（名次點 −2.87）。原因是押引公式有沒計入的因素（棄和後的流局聽牌、名次……）。
  所以預測參數用對數損失調整，押引參數（`push.*`）用 duplicate 調整。出處：M8 第 1 項。
- **決策參數的調整目標是 duplicate，不是反事實評估**（M8）。反事實是局部評分、雜訊大，又有挑選偏差。調參後要換 seed 再驗證，避免對同一組牌山過度調整。
- **場地對戰（`--field`）用來分開「對誰有效」**（M10）。A、B 不同桌，各自和三家同一個對手打；必須搭配不讀牌的對照組（greedy）確認效果的來源。

## 讀牌與印象操作

- **讀牌預測以天鳳鳳凰卓牌譜的邏輯迴歸校準，再用另一天的牌譜驗證**（M6）。自我對戰的機器人打法與真人不同（例如副露 1 組時真人只有 25% 聽牌，自我對戰是 43%）。出處：M4、M6。
- **讀牌接入決策後，自我對戰沒有變強**（M6）。原因推測：
  - 重抽時線索消失；
  - 機器人對手幾乎都立直；
  - 何切的損失主要在牌效判斷。
- **印象操作 = 用自己的讀牌模型看自己**（M10，`utils/image.rs`）。專案的讀牌模型本身就是合理的讀牌者，可以直接拿來當作對手的眼睛。
- **迷彩必須「點數不比較低」**（M10）。沒有這個條件時，面對不讀牌的對手會顯著變差（−0.24 ± 0.17）：看起來安全的聽牌常常比較便宜。
- **手切摸切單獨沒有效果**（M10）。策略聽牌幾乎都立直（默聽和只佔 0.4% 的局），沒有東西可藏。
- **反詐騙（流局對照修正）無效但保留**（M10）。一場半莊只有一兩次荒牌流局，樣本太少；要有效需要跨場的對手記憶。

## 外部 AI

- **Mortal 只透過 mjai 協定以子行程溝通，原始碼與權重隔離在 `tools/mortal`**（M8）。AGPL 不影響本專案。權重 S42（Apache-2.0）與 hhim8826（AGPL）由使用者選定。
- **與 Mortal 比較得到的策略弱點**（M8，尚未處理）：
  - 立直時機：策略在很多 Mortal 與高手默聽的局面立直；
  - 開槓：只因「不影響牌效」就暗槓；
  - 無人立直時的何切：與 S42 的一致率 56%，高手是 78%；
  - 鳴牌：S42 鳴得比策略多。

  M7 的復盤也發現兩點：
  - 漏鳴（策略會鳴、高手不鳴）時，高手平均好 660 點；
  - 牌效相近時，高手看打點與形狀的判斷較好。

## 練習 App

- **UI 與核心分離：`mj-app` 的 `App::call(名稱, JSON)` 是唯一入口**（M9）。網頁版（`mj serve`）與 Tauri 共用，前端依環境選擇呼叫方式。
- **先做瀏覽器版、再打包桌面版**（M9）。開發容器沒有 GUI；三平台安裝檔由 GitHub Actions 建置。
- **seed 限制在 53 位元**（M9）。這樣 JavaScript 能精確顯示與輸入，畫面上的 seed 可以重現對局。
- **白（5z）加上藍框**（M9）。原圖是全空白，圖片沒載入時與白無法分辨，曾被誤報成引擎 bug。

## 規劃

- **其他麻將規則延後，策略編輯便利性與 UI／UX 優先**（2026-10-13 重新規劃，M11–M16）。
- **M16 策略編輯流程採「參數即時編輯＋監看自動重建重啟」（A＋B）**（2026-10-13 使用者選定）。

  否決的方案：
  - 嵌入式腳本語言：重寫成本最高、慢 10–50 倍；
  - 外部行程策略：反事實實驗需要跨行程複製記憶；
  - 熱重載動態函式庫：Rust 沒有穩定 ABI，暫不做，如果 B 的等待太長再考慮。
